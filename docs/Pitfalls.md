# 開発時の落とし穴(Pitfalls)

このプロジェクトで踏んだ穴を書く。**コードやシーンを触る前に一度読む。**
ここが育つまでは、Godot全般の落とし穴を `砂時計pvp/docs/Pitfalls.md` で確認する
(書き出した版でだけ壊れる穴・GDScriptの型・`.tscn` の扱いなど、このプロジェクトにもそのまま当てはまる)。

## 描画

- **Zen Kaku Gothic New には ✓ ✔ ⚠ が無い。**デスクトップではOSのフォントで代わりに出ることがあっても、
  Web版では豆腐になる。記号は `UiDraw` で形を描く(★ ● ◆ ▲ ▼ → × ¥ … 〜 はある)。
  足す前に `fontTools` で `getBestCmap()` を引いて確かめる
- **フォントは使う字だけに絞ってある。**文言を足して check.sh のフォントの確認が NG になったら `python tools/subset_font.py` を回す。
  デスクトップでは足りない字をOSのフォントが補うので、画面を見ても気づけない
- **`Control._draw()` は自分の子より背面に描かれる。**背景の空を子の `SkyBackdrop` で置くと、画面自身の `_draw()` で
  描いた絵が空に隠れる。空と絵を同じ `_draw()` で描く画面は `SkyBackdrop.paint()` を呼ぶ
- **`CanvasItem` の描画ははみ出しを切らない。**通りの明かりのように隣の部品へ漏らしたくないものは、
  円ではなく片側だけの形(半円)で描く
- **大きな画像を小さく描くとギザギザになる。**256pxの絵を40px前後で描くときは、`.import` の `mipmaps/generate=true` と
  `rendering/textures/canvas_textures/default_texture_filter=2`(Linear Mipmap)の両方が要る。絵を足したら `.import` を確かめる

## データ

- **`.tres` の辞書は、キーを並べ替えて保存される。**手で書くときもキーを名前の順に並べておくと、エディタで開き直したときに差分が出ない
- **`--script` で動かすスクリプトの本体は、autoload を登録する前にコンパイルされる。**本体から autoload(`GameSession` など)を
  名前で参照するとコンパイルに失敗する。`root.get_node("GameSession")` で実行時に引く。`GameDatabase` を autoload にしていないのもこのため

## GDScript

- **Godot の組み込みの名前と同じ定数・内部クラスは、別の意味で読まれてコンパイルに失敗する。**`const KEY_ENTER` は
  キーの列挙 `KEY_ENTER` と比べられて「Key と String は比べられない」、内部クラス `Side` は列挙 `Side` と読まれて
  「列挙の値からプロパティは取れない」で止まった。`KEY_` `SIDE_` などの接頭辞と、`Side` `Key` などの列挙の名前は使わない

## オンライン対戦

- **ブラウザは裏に回したタブの描画(requestAnimationFrame)を止めるので、Web版はタブを離れると試合も通信も止まる。**
  相手からは無通信に見える。止まった側を「通信が切れた」として扱う(GameDesign.md 13.3節)
- **Workers の新しいURLは、デプロイの直後しばらく `error code: 1042` を返すことがある。**数十秒待てばつながる

## 数値

- **突発イベントの予告の早さは、イベントの最短の間隔(15秒)より短くする。**予告が間隔より早いと、1つ前のイベントが始まる前に
  次の予告を出すことになり、予告が遅れて届く(データ分析の予告を+10秒にして踏んだ)
- **勝敗が利益なので、原価や無料の商品のように「そのまま利益になる効果」は小さな数でも勝率に強く効く。**
  試合ごとのばらつきが小さく、利益が1万円違うだけで勝率が8割を超える

## 保存

- **テストやスクリーンショットで試合を最後まで回すと、`GameSession.finish_match()` が戦績を保存する。**
  本物の `user://save.cfg` を書き換えないよう、`GameSession.save` をテスト用のファイルの `SaveData` に差し替えてから回す

## 検証

- **`--import` は登録をしないまま終わることがある。**新しい class_name を足したあと check.sh が `--import` を回したのに、
  ログがバナー1行だけでキャッシュに載らず、テストが `Identifier "…" not declared` で止まった(手で `--import` を回し直すと通った)。
  check.sh は import のあとに登録を確かめ直し、載っていなければ Godot を回さず NG にする。そうなったら手で `--import` を回す
- **`--script` で動かすスクリプトはコンパイルに失敗すると `quit()` に届かず、終わらない。**check.sh はログに
  `Parse Error` などが出た時点で止めるので、時間切れまで待たない
- **試合の天気は乱数で引かれるので、画面のテストは天気で結果が変わる。**雨の日は開店直後に客を逃し、その出来事のヒントが先に出る。
  特定の流れを確かめるテストは `GameSession.weather_id` を固定してから試合を開く
- **`simulate.gd` は並列で回すと、親のプロセスが何も出さずに終了コード1で終わることがある。**全天気を一度に回すと起きやすく、
  1天気でも10回に3回ほど起きた。`weather=` で天気ごとに回し、終了コードが0でなければ回し直す(同じ種なので結果は変わらない)
