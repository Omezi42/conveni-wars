# 1章 試合の流れ

## 1.1 全体

1. 店長を選ぶ(7章)
2. 試合(300秒)。止まらずに進み、プレイヤーは好きなときに操作する(6章・5章・4章・7章)
3. 結果発表

## 1.2 時間帯

試合は店の1日(6:00〜24:00)を早回しで進める。4つの時間帯を順に進み、時間帯ごとに来る客層の割合と人数が変わる(2章)。

| 時間帯 | 長さ | 店の時計 | 来店数(両店の合計) | 主な客層 |
|---|---|---|---|---|
| 朝 | 75秒 | 6:00〜10:00 | 550人 | 会社員・学生・高齢者 |
| 昼 | 75秒 | 10:00〜14:00 | 650人 | 会社員(ラッシュ)・主婦・高齢者 |
| 夕方 | 75秒 | 14:00〜19:00 | 500人 | 学生・主婦・会社員 |
| 夜 | 75秒 | 19:00〜24:00 | 300人 | 若者・夜勤・会社員 |

- 1日の来店数は両店あわせて2,000人。実際のコンビニ1店舗の1日の客数(約1,000人)を2店で取り合う規模にするため
- 店の時計は時間帯の中で一定の速さで進める(時間帯によって進む速さが違う)
- 画面には**店の時計・いまの時間帯・次の時間帯の客層予報**を常に出す(9章)。先回りして発注させるため
- 試合開始時に10秒の**開店準備**があり、その間は客が来ない。最初の発注と配置をする時間
  (開店準備は300秒に含めない)。初回ガイドの間は開店準備の時計を止める(9.7節)

## 1.3 資金

- 開始時の資金は **30,000円**
- 発注すると資金が減り(6章)、商品が売れると売値がその場で資金に加わる
- 資金が足りない発注はできない
- **利益** = 売上 − 仕入れに払った額(発注の代金の合計)。資金は「開始時の資金 + 利益」なので、資金の増えた分が利益になる
- ふつうのCPUどうしの実測で、1店の1試合の売上は約78万円、利益は約29万円

## 1.4 勝敗

- 試合終了時の**利益**が多いほうが勝ち
- 同じなら来店した客の数が多いほうが勝ち。それも同じなら引き分け
- 仕入れすぎ・廃棄・安売りがどれも点数に直接効くようにするため、売上ではなく利益で競う

## 1.5 調整の目標

数値は次を満たすように、CPU対CPUのシミュレーション(Architecture.md 6章)で決める。

- 店長ごとの勝率(同じ店長どうしの試合を除く)が 40〜60% に収まる
- 棚を一度も変えない「固定の棚」のCPUが、予報を読むCPUに勝てない(勝率40%未満)
- 「常に強気」「常に安売り」のように値段を固定したCPUが、ふつうのCPUに勝ち越さない(勝率50%以下)
- 見込みの2倍を発注して「買い溜め」するCPUが、ふつうのCPUに勝ち越さない(勝率50%以下)
- 突発イベントの売上が、1店の売上の20〜30%に収まる(11.1節)
