# 10章 技術方針

- Godot 4.6 / GDScript 2.0。Web(HTML5)で書き出して unityroom で配布する
- unityroom のサムネイルは、売れていく試合の動きを見せる正方形のGIF(512×512・512KB以下)にする。一覧で遊びの中身が伝わるようにするため
- Webの読み込み中は、タイトルと同じ絵(夕暮れの通りに向かい合う2軒の店と題字)を出す。開いた瞬間から何のゲームかが分かるようにし、白い画面で待たせないため
- Webの初回読み込みは、回線30Mbpsで起動まで6秒以内を目標にする。エンジン本体は作り直さず、フォントを画面に出す字だけに絞って軽くする
- Web専用の機能(結果の共有・ダウンロード)は `JavaScriptBridge` で呼び、デスクトップでは同じボタンをファイル保存に置き換える。どちらの版でも同じ画面で遊べるようにするため
- 表示は 1280×720 を基準に、`canvas_items` で拡大縮小する。マウスとタッチの両方で操作できるようにする
- 商品・客層・時間帯・セット・店長・数値の設定はデータ(`.tres`)で持ち、コードへ書かない
- 試合のロジックは画面から切り離し、乱数の種を固定すれば同じ結果になるように作る
  (ヘッドレスのテストとバランス調整のシミュレーションで回すため)
- 試合中のプレイヤーのコマンドを、何tick目(`advance` を呼んだ回数)に出したかと一緒に記録する。
  同じ種・同じCPUの強さ・同じコマンド列で再生すれば同じ結果になる(結果画面の「CPUならどうしたか」に使う。9.4節)
